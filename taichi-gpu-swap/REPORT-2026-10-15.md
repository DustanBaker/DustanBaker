## Qwen3.8-Flash-Next — what happened and why it must not be retried as-is
- `-ngl 99 -fit off` with 88 GB of weights starved the display card's VRAM → Hyprland aborted, SDDM restarted the session,
  kernel OOM killed llama + the Hermes gateway (16:43).
- With fit mode (weights mmapped on the CPU side), **Vulkan model loads stage through GTT and amdgpu's TTM page pool keeps
  those pages** (3.6 M pages ≈ 14 GB; default limit = half of RAM). Two attempts drove MemAvailable to 0 and the second one
  ended in a kernel memory deadlock/panic (17:15). Partial numbers before the abort: dual card pp512 ≈ 884 tok/s, tg ≈ 27–29 tok/s;
  single card pp30000 134 tok/s, tg 5.6 tok/s (paging from NVMe).
- The test script now: fit mode with a 3 GB margin on the display card, `--no-host`, a MemAvailable watchdog (SIGKILL below 3 GB),
  TTM pool shrink (`drop_caches=2`) before every load, `CONFIGS=dual`, and runs inside `systemd-run --scope -p MemoryMax=24G`.

## Decisions for Dusty
1. **Production service.** Recommended: `build-vulkan/bin/llama-server -m ~/models/qwen3.8-27b/Qwen3.8-27B-Q8_0.gguf --mmproj
   ~/models/qwen3.8-27b/mmproj-F16.gguf -ngl 99 -fit off --no-host --jinja -fa on -c 131072 --device Vulkan0,Vulkan1 -sm layer`
   (262144 also fits with 16 GB spare). To keep Hermes/Qwen Code untouched, stop ollama and bind llama-server to `127.0.0.1:11434`
   (its `/v1` API ignores the model name), or keep ollama and point Hermes at a new port.
2. **TTM pool cap** (prevents the RAM exhaustion seen during big loads): `options ttm page_pool_size=524288` (2 GB) in
   `/etc/modprobe.d/ttm.conf` + `mkinitcpio -P` + reboot. Only matters for models that do not fit VRAM; recommended anyway.
3. `gpu-crash-watch.service` (NVIDIA Xid watcher) is still enabled; harmless, can be disabled.
4. The 89 GB Flash-Next download in `~/models/Qwen3.8-Flash-Next-AD-4.27bpw-Q4_K_M-M64/` can be deleted (90 GB free now).
5. ROCm investigation as a follow-up; Vulkan is already faster than the published ROCm-on-R9700 numbers for generation.

### Runtime power management must be off on the compute card
`0000:4e:00.0` (no display) runtime-suspends when idle (42 times in one boot) and **amdgpu evicts its VRAM to system RAM
on every suspend**: 14 GB of GTT, MemAvailable 4 GB, 0.75 tok/s on the first request after a resume, and the desktop
session restart at 22:18. Fix (root): `echo on | sudo tee /sys/bus/pci/devices/0000:4e:00.0/power/control` now, and
`units/80-amdgpu-no-runtime-pm.rules` → `/etc/udev/rules.d/` + `sudo udevadm control --reload && sudo udevadm trigger -s pci`
to make it permanent. (`amdgpu.runpm=0` on the kernel cmdline is the alternative.)
